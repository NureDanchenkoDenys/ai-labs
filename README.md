# Інтелектуальна система керування списком покупок

Навчальний проєкт із дисципліни «Штучний інтелект у програмній інженерії» (ЛР №1–№2).

**Команда:** Данченко Денис; Пархоменко Олександр.
**Базова специфікація (ЛР1):** `lab01-spec` (19.11.2026).
**Поточний етап (ЛР2):** реалізовано локальний REST API на **Python, FastAPI, SQLite, pytest** у межах `FR-01`–`FR-08` (зрізи `A–E`, маршрути `API-01`–`API-10`) та проведено експеримент порівняння реалізації без AI та з AI.

## Мета та функціональність системи

Система є локальним вебсервісом для ведення списків покупок через REST API та інтерактивну документацію Swagger UI (`/docs`). Користувач може:

- створювати іменовані списки покупок і переглядати їх (`FR-01`, `FR-03`);
- читати фіксований довідник із 10 категорій товарів (`API-02`);
- додавати товарні позиції з назвою, кількістю, одиницею вимірювання (`шт`, `кг`, `г`, `л`, `мл`, `уп`) та категорією (`FR-02`);
- частково редагувати поля позиції з атомарною перевіркою та rollback при помилці (`FR-04`);
- видаляти позиції (`FR-05`) та змінювати стан придбання у двох напрямках (`FR-06`);
- фільтрувати позиції списку за `category_id` та `is_purchased` з логічним `AND` (`FR-07`);
- отримувати загальну та покатегорійну статистику позицій у списку (`FR-08`).

> **Поза обсягом ЛР2 (`ЛР4`):** `FR-09` (`API-11 POST /recommendations/category` — семантична NLP-рекомендація категорії з підтвердженням користувача) свідомо відкладено до ЛР4 і в поточній версії не реалізовано. Також поза обсягом специфікації залишаються автентифікація, ролі, ціни, бюджет, видалення або перейменування списків і редагування довідника категорій через API (див. [docs/requirements.md](docs/requirements.md)).

## Реалізовані HTTP-маршрути (`API-01`–`API-10`)

Повні схеми запитів, відповідей і формат помилок (`detail.code`, `detail.message`, `detail.fields`) визначено в [docs/api-contract.md](docs/api-contract.md).

| ID | Метод і шлях | Призначення | Вимоги |
| --- | --- | --- | --- |
| `API-01` | `GET /health` | Перевірка запуску HTTP API | `NFR-01` |
| `API-02` | `GET /categories` | Читання фіксованого довідника | `FR-02`, `FR-04`, `FR-07`, `FR-08` |
| `API-03` | `POST /lists` | Створення списку | `FR-01` |
| `API-04` | `GET /lists` | Перегляд списків | `FR-03` |
| `API-05` | `GET /lists/{list_id}` | Метадані та позиції списку, фільтрація | `FR-03`, `FR-07` |
| `API-06` | `POST /lists/{list_id}/items` | Створення позиції | `FR-02` |
| `API-07` | `PATCH /lists/{list_id}/items/{item_id}` | Зміна основних полів | `FR-04` |
| `API-08` | `DELETE /lists/{list_id}/items/{item_id}` | Видалення позиції | `FR-05` |
| `API-09` | `PATCH /lists/{list_id}/items/{item_id}/purchase` | Зміна придбання | `FR-06` |
| `API-10` | `GET /lists/{list_id}/statistics` | Загальна статистика й категорії | `FR-08` |

*Майбутній маршрут `API-11 POST /recommendations/category` (`FR-09`) відкладено до ЛР4.*

## Збереження даних у SQLite

- **Робоча база даних:** локальний файл `database.db` у корені репозиторію (`DEFAULT_DB_PATH` у `app/db.py`, ігнорується Git).
- **Ініціалізація та довідник:** під час запуску FastAPI (`lifespan`) виконується ідемпотентна функція `init_db()`, яка створює таблиці `categories`, `shopping_lists`, `shopping_items`, індекси `(list_id, created_at, id)` і `(list_id, category_id, is_purchased)` та наповнює 10 нормативних категорій (`id` `1..10`) за [docs/requirements.md](docs/requirements.md) через `INSERT OR IGNORE`.
- **Цілісність і точність кількості:** на кожному з'єднанні вмикається `PRAGMA foreign_keys = ON`. Поле `quantity` зберігається в БД як ціле `quantity_milli = quantity × 1000` (`1..10_000_000`) із десятковою арифметикою без тихого округлення (для `шт` і `уп` `quantity_milli % 1000 = 0`).
- **Транзакції:** операції запису виконуються в `BEGIN IMMEDIATE` із `rollback` при помилці; обчислення загальної й покатегорійної статистики (`API-10`) виконується в одній read-транзакції (`BEGIN DEFERRED`) для узгодженого знімка даних.
- **Ізоляція тестів (`NFR-04`):** інтеграційні тести API й БД використовують ізольовані тимчасові SQLite-бази через `tmp_path` (`tests/conftest.py`) і не змінюють робочий файл `database.db`, а тести експериментальних чистих Python-функцій (`tests/test_experiment_lr2.py`) працюють без SQLite.

## Вимоги та встановлення (Windows PowerShell)

- **Python:** версія **не нижче 3.10** (у коді та тестах використовуються синтаксис об'єднання типів `X | Y` та `zip(..., strict=True)`).

1. Створіть віртуальне середовище `.venv` у корені репозиторію:

   ```powershell
   python -m venv .venv
   ```

2. Активуйте віртуальне середовище:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

   *(Якщо політика виконання PowerShell обмежує скрипти активації, усі наступні команди можна запускати без активації через `.\.venv\Scripts\python.exe`.)*

3. Встановіть зафіксовані версії залежностей із [requirements-lock.txt](requirements-lock.txt):

   ```powershell
   python -m pip install -r requirements-lock.txt
   ```

   Файл [requirements.txt](requirements.txt) містить лише перелік прямих залежностей верхнього рівня (`fastapi`, `uvicorn`, `httpx`, `pytest`, `ruff`) без зафіксованих версій — для відтворюваного встановлення використовуйте [requirements-lock.txt](requirements-lock.txt).

> **Підтверджено локально (`NFR-01`):** у чистому тимчасовому середовищі (Windows PowerShell, Python `3.14.5`) встановлено 24 пакети з [requirements-lock.txt](requirements-lock.txt), запущено FastAPI/Uvicorn (`GET http://127.0.0.1:8000/health` → HTTP `200`, `{"status":"ok"}`), `python -m pytest -q` показав `163 passed, 1 StarletteDeprecationWarning` (`3.91 s`), `Ruff` — `All checks passed`.

## Запуск API та перевірка роботи

1. Запустіть локальний сервер FastAPI:

   ```powershell
   python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

2. Перевірте доступність сервісу (`API-01`):
   - `GET http://127.0.0.1:8000/health` — очікувана відповідь `200 OK` з тілом `{"status": "ok"}`.
3. Відкрийте інтерактивну документацію Swagger UI:
   - `http://127.0.0.1:8000/docs`.

## Запуск тестів і статичного аналізу

Виконуйте команди з кореня репозиторію в активованому `.venv`:

```powershell
python -m pytest -q
python -m ruff check app tests experiments --select E4,E7,E9,F,I
```
